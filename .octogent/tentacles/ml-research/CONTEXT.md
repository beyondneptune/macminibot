# ml-research

Walk-forward, dollar-bar-fed, gradient-boosted return predictor with a strict feature/registry contract to `strategy-engine`.

## Status
Greenfield → first training run complete. **Substrate, methodology, and architecture ratified 2026-05-17; cycle-5 training run flipped the production model.** On the bootstrap dataset (8 symbols × 9 daily-bar features, 4 dollar-bar features still deferred), **Ridge OOS Sharpe = +0.452 vs LightGBM +0.015** and Ridge IC = +0.021. Per the CONTEXT line 148 hard rule ("LightGBM must beat Ridge OOS Sharpe per fold or it is rejected as overfit"), **Ridge is promoted to v0 production**; LightGBM is demoted to "candidate, currently rejected as overfit at this data scale". Re-bake-off is mandatory once (a) the 4 dollar-bar features land and (b) the universe expands beyond 8 symbols — whichever comes first triggers a new fold sweep before any model swap.

## Scope
- Feature engineering library (the **canonical** feature implementation reused by `strategy-engine` at inference time — single source of truth, training-serving parity enforced by CI)
- Label generator (continuous next-day open-to-close log return, winsorized + xs z-scored)
- Walk-forward training pipeline (expanding-window, embargoed/purged, monthly refit) over dollar bars + daily bars from `market-data` ArcticDB
- LightGBM trainer (primary) + Ridge fallback (sanity)
- Model registry: versioned artifacts with `{git_sha, data_window, feature_spec, hyperparams, metrics, artifact_path, model_version}` manifest
- Offline evaluation: per-fold + aggregate IC, hit rate, OOS Sharpe; SHAP-based attribution; regime-conditional eval
- Live inference adapter: stateless function `predict(features) -> Signal` consumed by `strategy-engine`
- Drift monitor: daily KS-test on live feature distributions vs the training fold's distribution
- Shuffle-label canary in CI: any pipeline change that yields positive OOS IC on shuffled labels fails the build (leakage detector)

## Boundaries
- **Owns:** features library, label generator, walk-forward harness, LightGBM/Ridge trainers, model registry + manifest schema, SHAP/eval reports, drift monitor, inference adapter
- **Consumes from:** `market-data` (read API over ArcticDB libraries `<asset_class>.dollar_bars` and `<asset_class>.daily_bars`); `backtesting` (full strategy evaluation harness for end-to-end model validation); `shared-core` (`Symbol`, `Venue`, timestamp + decimal helpers)
- **Provides to:** `strategy-engine` (model artifacts, feature spec, `predict()` adapter, model_version registry handle); `backtesting` (signal generators to test); `observability` (training/eval metrics, drift KS p-values)
- **Does NOT own:** risk checks (`risk-management`), order routing (`execution`), live feature serving infrastructure (the runtime feature path is the same Python module imported in `strategy-engine`, not a separate service), data storage (that's `market-data`)

## Signal contract (locked, consumed by `strategy-engine`)

**Source of truth: this CONTEXT.md.** The concrete dataclass below is the canonical schema. `shared-core` MUST mirror it verbatim as a `@dataclass(frozen=True)` in `shared_core.contracts.signal` (no field reordering, no renaming, no type widening). Both `ml-research.inference` and `strategy-engine.intent` import the symbol from `shared_core.contracts.signal` — neither tentacle defines its own copy. A CI test in `shared-core` asserts the dataclass fields, types, and frozen flag match this spec byte-for-byte (e.g. via `dataclasses.fields(Signal)` introspection compared against a checked-in golden tuple derived from this section).

```python
# shared_core/contracts/signal.py — mirror of the spec defined here
from dataclasses import dataclass
from decimal import Decimal
from shared_core.contracts.symbol import Symbol  # already in shared-core

@dataclass(frozen=True, slots=True)
class Signal:
    symbol: Symbol              # from shared-core
    r_hat_daily: Decimal        # predicted next-day open-to-close log return, DECIMAL (e.g. Decimal("0.0042")), NOT a z-score
    confidence: float           # in [0.0, 1.0], from paired LightGBM (0.1, 0.9) quantile spread; see Conventions
    model_version: str          # opaque registry handle, used by observability and audit log
    as_of_ns: int               # int64 nanoseconds since UNIX epoch, UTC, timestamp features were computed against
```

Import path contract:
- `ml_research.inference.predict` returns `shared_core.contracts.signal.Signal`.
- `strategy_engine.intent.from_signal` accepts `shared_core.contracts.signal.Signal`.
- Neither tentacle redefines the dataclass. If a field must change, the change lands in `shared-core` first and this section is updated in the same PR.

The model trains on cross-sectional z-scores (numerically well-behaved across regimes), but the inference adapter **inverts the z-score** using the cross-section's daily mean/std snapshot stored in the model artifact, so `strategy-engine` receives a raw decimal return prediction and never has to reason about z-scores. This keeps the strategy-engine math regime-agnostic and decouples sizing from label normalization.

## Key Decisions (ratified 2026-05-17)
- **Primary substrate: dollar bars** from `market-data` (`<asset_class>.dollar_bars`) — López de Prado, *Advances in Financial ML* Ch. 2. Daily bars (`<asset_class>.daily_bars`) used for the slow-factor subset of features only.
- **Baseline model: LightGBM, pooled cross-sectionally with contract-ID one-hot, regression target.** Reason: Gu/Kelly/Xiu (RFS 2020, *Empirical Asset Pricing via Machine Learning*) demonstrate tree ensembles dominate linear models at our universe size. We are **nowhere near** the Kelly/Malamud/Zhou *Virtue of Complexity* (JF 2024) regime, which requires `N_features >> N_obs` across thousands of names; that regime is for transformer-scale random-feature ridge, not our 12-feature setup.
- **Ridge regression is the fallback / sanity-check floor**, not a production candidate. Every LightGBM model must beat Ridge OOS Sharpe per fold; if it doesn't, the LightGBM is overfit and the model is rejected.
- **12 features** (locked v1):
  1. `ret_1d` — 1-day return
  2. `ret_5d` — 5-day return
  3. `ret_21d` — 21-day return (~1 month)
  4. `ret_252d_skip_21` — 12-1 momentum, Jegadeesh-Titman (JF 1993)
  5. `gap_overnight` — close-to-09:35-ET-5min-bar gap (derived from dollar-bar boundary nearest 09:35 ET)
  6. `realized_vol_21d` — 21-day realized vol (close-to-close)
  7. `parkinson_vol_21d` — Parkinson high-low estimator over 21d (Parkinson 1980)
  8. `db_duration_mean_21d` — mean dollar-bar duration over last 21 trading days (Easley-López de Prado-O'Hara 2012 info-flow proxy)
  9. `db_signed_vol_imb_21d` — signed volume imbalance on dollar bars, 21d mean (order-flow proxy using tick-rule sign)
  10. `db_kyle_lambda_21d` — Kyle's lambda (Kyle 1985 *Continuous Auctions and Insider Trading*), 21d rolling regression of `|return|` on signed volume
  11. `vix_proxy` — cross-sectional realized vol of {SPY, QQQ, IWM} over 21d (no VIX vendor sub; this is the free proxy)
  12. `cross_sectional_rank_mom` — daily xs rank of `ret_21d` within the universe
  13. `rel_strength_vs_spy` — `ret_21d(symbol) - ret_21d(SPY)`

  (13 entries; "12 features" is shorthand — the `vix_proxy` is shared across all symbols on a given day, so feature **dimensionality** is 12 per-symbol + 1 broadcast. Locked as v1.)
- **Label**: continuous next-day open-to-close log return `r_{t+1} = log(close_{t+1} / open_{t+1})`, winsorized at ±5σ on the training fold's distribution, then daily cross-sectional z-scored. Continuous regression (not classification) because (a) sizing in `strategy-engine` is proportional to predicted magnitude, (b) classification throws away the magnitude signal that's most valuable for vol-targeted sizing.
- **Walk-forward CV**: expanding train window (min 5 yr, cap 15 yr — pre-2000 microstructure is non-stationary: decimalization 2001, Reg NMS 2007, MIFID2 2018), **252-day held-out validation** inside the train window for hyperparam selection, **5-day embargo + 1-day purge** between train-val and train-test boundaries (López de Prado *Advances in Financial ML* Ch. 7), **21-day test fold**, **monthly refit cadence**. CPCV (Combinatorial Purged CV) inside the train fold for hyperparam selection only (not for final OOS).
- **Biggest leakage risk: cross-sectional z-score contamination.** If the z-score is computed using statistics that include test-fold dates, IC will look spuriously good. Mitigation: a `PurgedPipeline` wrapper that fits **all** transformers (winsorization bounds, z-score mean/std, label clippers) on the train fold only, plus a CI shuffle-label canary test that fails the build if shuffled labels yield positive OOS IC.
- **LightGBM objective: `regression_l1` (MAE / Laplace likelihood)** — daily return residuals are heavy-tailed (kurtosis routinely >10 in tradable universes); L2 loss over-weights tail observations and degrades median rank correlation. L1 is the default; L2 kept behind a config flag for ablation. Citation: Gu/Kelly/Xiu use Huber for the same reason — L1 is the limiting case.
- **No deep learning, no transformers, no RL** — universe size, sample count, and feature count put us outside any published regime where these dominate at this horizon. Revisit only if L2 microstructure storage unlocks (then DeepLOB / OFI-CNN per Kolm/Turiel/Westray becomes worth a bake-off).
- **Model architecture A/B (monthly-base + meta-learner stack) deferred to post-baseline**, conditional on ≥6 months of accumulated dollar bars and a baseline LightGBM in production. Not on the v1 critical path.

## Regime taxonomy (pinned cycle 3, binding on `regime_conditional_eval` epic)
Each OOS prediction row is tagged with **three orthogonal regime labels** computed strictly from data available on `as_of_ns` (no look-ahead). Per-regime Sharpe / IC is reported as a 3-way crosstab plus marginals.

1. **Vol regime — `vix_proxy` quintile** (5 bins): rank `vix_proxy` (the same feature already in the model — xs realized vol of {SPY, QQQ, IWM} over 21d) against its **trailing-1260-day** (≈5y) rolling distribution as of `as_of_ns - 1d`, assign quintile `Q1..Q5`. Trailing window (not full history) keeps the bin definition stationary; full-history quantiles would put 2008 in Q5 forever and starve Q5 of recent samples.

2. **Trend regime — Hurst exponent on SPY, classified into 3 bins**: compute `H_t` via rescaled-range (Hurst 1951; implementation per Peters 1994, *Fractal Market Analysis*, using log-price `[t-252d, t-1d]` window, lags `n ∈ {10, 20, 40, 80}`). Classify: `H < 0.45 → mean_reverting`, `0.45 ≤ H ≤ 0.55 → random_walk`, `H > 0.55 → trending`. Bin edges are literature-standard (Peters); a CI test asserts the bin edges are not silently retuned.

3. **Dispersion regime — cross-sectional return-vol z-score, 3 bins**: on each day compute `xs_disp_t = std_i(ret_21d_i)` across the universe, z-score against its trailing-252d distribution. Bins: `z < -0.5 → compressed`, `|z| ≤ 0.5 → normal`, `z > 0.5 → dispersed`. Captures the "everything moves together" vs "stock picker's market" axis that vol-quintile alone misses (a high-VIX day with low dispersion is a beta day, not an alpha day).

Decision rule (carry-over from the epic): a model whose OOS Sharpe is positive in only one cell of the (5 × 3 × 3 = 45) crosstab is a **regime bet**, not alpha — document and ship anyway or kill. A model with Sharpe positive in ≥ 60% of populated cells (≥10 obs each) is a robust alpha. Borderline cases get a manual review note in the SHAP report.

Why these three: vol, trend, and dispersion are the three independent axes that *Empirical Asset Pricing via Machine Learning* (Gu/Kelly/Xiu 2020) identify as conditioning the equity factor zoo's IC. Adding more axes (sentiment, macro, term-structure) is post-baseline; these three are the locked v1 taxonomy.

## Improvements added beyond baseline (2026-05-18, cycle 2)
4. **Sample weight by label uniqueness** (López de Prado, *Advances in Financial ML* Ch. 4, "Sample Weights"). Our 21-day forward-overlapping evaluation horizon and pooled cross-sectional training mean training rows are **not** IID — label periods overlap, so naive ERM over-weights densely-overlapping regimes (e.g. the 2020 COVID cluster) relative to sparse ones. Mitigation: compute `avg_uniqueness_i = mean over t in label_i_span of (1 / concurrent_label_count_t)` per training row, pass to LightGBM via `sample_weight=avg_uniqueness`. Cheap to compute (one pass over label spans), proven to reduce variance of IC across folds, and orthogonal to every other ratified choice — no architectural change, no new dependency. Owned by new Epic in `todo.md`.

## Improvements added beyond baseline (2026-05-17)
1. **Inference-time z-score inversion in the signal contract.** Train on z-scores (numerically stable across regimes); invert in the registry-attached snapshot so `strategy-engine` consumes a decimal return, not a z-score. This closes the latent integration gap with `strategy-engine` (whose `OrderIntent` math is currently undefined — it needs a position-sizing primitive that scales with return magnitude, not a unitless rank). Documented in **Signal contract** above.
2. **Shuffle-label canary as a CI gate, not just a dev script.** The single most common silent failure in cross-sectional ML pipelines is z-score leakage (see López de Prado, *Advances in Financial ML* Ch. 7; Arnott/Harvey/Markowitz 2019, *A Backtesting Protocol in the Era of Machine Learning*). Making it a CI gate — pipeline change → shuffle labels → if OOS IC > 2σ of null, fail the build — converts a deferred-debug class of bug into a build break. Owned by Epic 3.
3. **LightGBM `objective=regression_l1` made explicit and load-bearing**, not left as a hyperparameter sweep target. Heavy tails in daily returns (kurtosis >10 typical for equity universes; see Cont 2001, *Empirical properties of asset returns: stylized facts and statistical issues*) mean L2 loss is dominated by ~10 outlier days per year and degrades the rank correlation that actually drives Sharpe. Codified as a Key Decision so a future contributor doesn't quietly flip it to L2 in a hyperparam config.

## Negative results (2026-05-18, cycle 7)
**Cross-asset spread features rejected.** Implemented as `CANDIDATE_XS_SPREAD_FEATURES = (ret_21d_xs_spread, ret_5d_xs_spread, realized_vol_21d_xs_spread)` in `src/ml_research/features.py` (computed as `feature(symbol) - mean(feature of {SPY, QQQ, IWM})`), trained via `scripts/11_train_with_xs_spreads.py` against the recomputed cycle-6 baseline on the same 336 walk-forward folds.

Result (336 folds, Ridge, 8 tradable symbols):
- **Baseline (9 features)**: mean IC = +0.0210, mean Sharpe = +0.452 — reproduces the cycle-6 anchor exactly.
- **Candidate (9 + 3 xs-spread)**: mean IC = +0.0213, mean Sharpe = **+0.301**.
- Per-fold deltas: mean ΔIC = +0.0003 (essentially zero), mean ΔSharpe = **−0.151**. Folds with ΔIC ≥ +0.005: **66/336** — well below the "≥4-of-6 ≈ 67%" promotion bar.

Verdict per CONTEXT improvement #12 promotion rule: **FAIL** on (a) IC-lift threshold AND **FAIL** on (c) Sharpe floor (+0.301 < +0.452). Two-of-three failed before the shuffle canary even ran. `feature_spec_hash` is **not** bumped; the candidate features are kept in `CANDIDATE_XS_SPREAD_FEATURES` (not in `FEATURE_NAMES`) so they remain easy to re-test once the universe expands.

Root-cause hypothesis (not load-bearing — documented for the next attempt): with only 8 tradable symbols and {SPY, QQQ, IWM} as the basket, the basket mean is already implicitly proxying the broad equity market that `rel_strength_vs_spy` and `cross_sectional_rank_mom` capture from a different angle. The three xs-spread features are therefore near-collinear with the existing 9 — Ridge's `α=1.0` shrinkage redistributes weight across the redundant columns and the Sharpe degrades slightly because the noisier subtraction (vs a 3-symbol mean) introduces variance without adding signal. Re-test when the universe is ≥ 50 names and the basket can be expanded to sector ETFs (XLF, XLK, XLE, ...) — that is the regime Asness/Moskowitz/Pedersen 2013 actually studied; an 8-name universe is below the threshold where cross-asset spreads carry independent risk premia.

Next cycle-7 candidate to try: **family (b) VIX-proxy tercile 1-hot + `ret_21d × vix_high` interaction** (CONTEXT improvement #12b). Distinct from xs-spreads in that it adds *non-redundant* regime-conditional drift, which Ridge cannot express via the locked feature set at all (no splits, no interactions).

## Negative results (2026-05-18, cycle 10)
**Training-time vix_high filter rejected.** Hypothesis: after cycles 7-9 showed three feature families could not lift Ridge and the cycle-9 regime stratification revealed vix_high net Sharpe = −0.252 in the end-to-end driver, perhaps Ridge's coefficients are being *contaminated* by the vix_high training rows. Test: drop training-fold rows where `RegimeTagger.tag(date) == "vix_high"` (rolling-252d quintile cutoffs, same causal shift(1) discipline as `_vix_tercile_features`); evaluate on the full unchanged test set. Implemented in `scripts/15_train_ridge_vix_filtered.py`.

Result (336 folds, Ridge, 8 tradable symbols, regime distribution low=3098 / mid=6988 / high=1353 days):
- **Baseline (full train set)**: mean IC = +0.0210, mean Sharpe = +0.452 — anchor reproduced exactly.
- **Filtered (drop vix_high train days, train n shrinks ~20%)**: mean IC = +0.0203, mean Sharpe = **+0.386**.
- Per-fold deltas: mean ΔIC = −0.0007, mean ΔSharpe = **−0.066**. Folds with ΔIC ≥ +0.005: **126/336 (38%)** — below the 67% promotion bar.
- Per-regime weighted test Sharpe (raw ridge prediction Sharpe, no fees):
  - vix_low : base **+0.881** → filtered **−0.325** (Δ = **−1.206**, catastrophic)
  - vix_mid : base +0.684 → filtered +0.744 (Δ = +0.060, marginal lift)
  - vix_high: base +0.611 → filtered +0.466 (Δ = −0.145, hurt)

Verdict per CONTEXT improvement #12 promotion rule applied to a training-filter variant: **FAIL** on (a) IC-lift threshold AND **FAIL** on (c) Sharpe floor (+0.386 < +0.452). The filter is **worse on every regime except vix_mid**, and the vix_low collapse (−1.21 Sharpe!) is the most damaging single number: removing vix_high days re-centres the training feature distribution toward calm regimes, but the resulting model overfits to the now-narrower vol regime and breaks on the test-side vix_low (which is structurally different from vix_mid even though both are "calm"). The decision is **not** load-bearing on a single hypothesis but rather establishes a regime-fit principle: a single-head Ridge cannot have its training distribution surgically narrowed without paying for it on every test regime.

Note on the cycle-9 vs cycle-10 vix_high Sharpe discrepancy: cycle 9 reported vix_high net Sharpe **−0.252** using `WalkForwardDriver` with Alpaca fees + slippage; cycle 10 reports vix_high raw prediction Sharpe **+0.611** (no fees, no slippage). These are consistent — the model's raw forecast has positive correlation with realised return in vix_high, but the predicted magnitudes are too small to clear the fee drag. This is a **sizing / cost-budget** failure in vix_high, not a sign-flip in the conditional mean. The right next experiment is therefore not "throw away vix_high training data" (rejected here) but "vol-target sizing OR regime-conditional position scaling so vix_high trades are either smaller or skipped at the strategy layer". That belongs to `strategy-engine`, not `ml-research`.

Verdict for ml-research: **Ridge v0 stays as-is on full-train**. `feature_spec_hash` not bumped. Variant (2) (two-headed regime-switch model) from the cycle-10 spec is also **shelved** — if narrowing one head's training distribution costs −1.2 Sharpe in vix_low, splitting into two heads is strictly worse (each head sees a narrower slice). Move regime-conditional behaviour to the sizing layer instead.

## Improvements added beyond baseline (2026-05-18, cycle 6)
11. **Ridge promoted to v0 production after cycle-5 bake-off (inverted Virtue-of-Complexity at our scale).** First training run: Ridge OOS Sharpe = +0.452, IC = +0.021; LightGBM OOS Sharpe = +0.015, IC ≈ 0. Per CONTEXT line 148 ("LightGBM must beat Ridge per fold or it is rejected as overfit"), Ridge wins. This is not a contradiction of cycle-1 reasoning — it is **exactly the regime Kelly/Malamud/Zhou 2024 (*The Virtue of Complexity in Return Prediction*, JF) characterize from the opposite end**: their result is that ridge with *N_features >> N_obs* dominates because the implicit shrinkage absorbs the noise that trees overfit; at our bootstrap scale (`N_obs ≈ 8 symbols × ~200 days ≈ 1,600` rows, 9 features, signal-to-noise ratio ~0.02), we sit in the **low-complexity** end of the same curve where ridge **also** dominates because LightGBM's `num_leaves≥31` splits have nothing to chew on — Gu/Kelly/Xiu 2020's tree-dominance result needs hundreds of features × thousands of names, which neither end of our growth path has yet. Decision: ship Ridge as v0 with the full Signal contract intact (Ridge quantile predictions via residual-bootstrap for `confidence`, since Ridge has no native quantile output); keep LightGBM in CI as the rejected challenger so the gate keeps firing. Re-bake-off triggers: (a) +4 dollar-bar features land (13 total) AND (b) universe ≥ 50 symbols — only then is the LightGBM-favouring regime plausibly reached. Pin: **do not delete the LightGBM trainer**; the bake-off must remain automatable for every refit, and the day Ridge loses (likely when N_obs × N_features crosses ~50k) the swap must be one-line.

12. **Feature-engineering shortlist to lift Ridge's IC (cycle-6 backlog seed).** Ridge IC = +0.021 is real but small; three families of features are cheap, ridge-friendly (linear-additive lift, not interaction-buried), and orthogonal to the locked 12. Pick at most one per refit to keep the spec-hash churn auditable:
    - **Cross-asset spread features** — pairwise return spreads within sector/factor pairs (e.g. `ret_5d(XLF) - ret_5d(XLK)`, `ret_5d(IWM) - ret_5d(SPY)`). Ridge can weight a dozen such spreads directly; trees would need a split per spread component. Rationale: sector dispersion drives cross-sectional rank that `cross_sectional_rank_mom` only captures globally. Reference: Asness/Moskowitz/Pedersen 2013, *Value and Momentum Everywhere* (JF) — cross-asset spreads carry independent risk premia.
    - **VIX-proxy regime indicator (binary/ordinal)** — bucket `vix_proxy` into a `{low, mid, high}` 1-hot triple (using the trailing-1260d quintile edges from the Regime Taxonomy section, collapsed to terciles). Adds 2 ridge coefficients; lets the linear model express regime-conditional drift (`ret_21d × vix_high`) that it otherwise cannot. Distinct from the **interaction-feature ban for LightGBM** in cycle-5 #9 — Ridge **needs** explicit interactions because it has no splits.
    - **Lagged-feature interactions, t−1 vs t−5** — `ret_1d_lag5`, `realized_vol_21d_delta_5d` (`vol_t − vol_{t−5}`). Captures short-horizon momentum reversal and vol-acceleration cheaply. Per Lo/MacKinlay 1990 (*An Econometric Analysis of Nonsynchronous Trading*, JoE) and the lead-lag literature, t−1 to t−5 cross-correlations carry the bulk of recoverable equity microstructure signal at the daily horizon. Each new lag must pass the shuffle-label canary individually (cycle-2 improvement #2 already gates this).

    Decision rule: any candidate feature must (a) lift aggregate IC by ≥ 0.005 on ≥ 4 of 6 walk-forward folds, (b) pass shuffle-label canary, (c) keep Ridge's OOS Sharpe ≥ current +0.452 baseline. Two-of-three fails. Bump the `feature_spec_hash` on every adopted feature and log the cycle-6 baseline IC = +0.021 / Sharpe = +0.452 / 9 features as the comparison anchor in `manifest.baselines.cycle6_ridge_v0`.

## Improvements added beyond baseline (2026-05-18, cycle 5)
8. **Evaluation metric set expanded beyond Sharpe (binding on `evaluate_fold`).** Sharpe alone hides three failure modes that the v1 gate must catch: (a) a model that's "Sharpe-positive" only because of one good year that masks a 40% drawdown, (b) a model whose Sharpe is statistically indistinguishable from zero given the OOS sample size, (c) a model that beats Ridge OOS but underperforms a passive SPY hold (in which case shipping it destroys value vs the trivial alternative). Pin the following metric quartet per fold + aggregate, all written to `manifest.per_fold_metrics` and `manifest.aggregate_metrics`:
   - **Calmar ratio**: `annualized_return / |max_drawdown|`. Calmar > 0.5 per fold is the deployability floor (industry rule of thumb; cf. Young 1991, *Calmar Ratio: A Smoother Tool*). A model with Sharpe 1.0 and Calmar 0.2 is shipping a tail-risk bomb; reject.
   - **Probabilistic Sharpe Ratio (PSR)** at the benchmark Sharpe of 0 (López de Prado & Bailey 2012, *The Sharpe Ratio Efficient Frontier*, JoR): `PSR(SR*) = Φ((SR - SR*) · sqrt(n-1) / sqrt(1 - γ_3·SR + ((γ_4 - 1)/4)·SR²))` where `γ_3, γ_4` are skew/kurtosis of daily returns. Reject any fold where `PSR(0) < 0.95` — i.e. you cannot reject "true Sharpe ≤ 0" at 95% confidence. This catches "lucky" folds that the bare Sharpe number doesn't flag.
   - **Information Ratio vs SPY benchmark**: `IR = mean(r_strat - r_SPY) / std(r_strat - r_SPY) · sqrt(252)`. Reject any fold where `IR ≤ 0` (passive SPY hold beat the strategy after costs). This closes the "Ridge sanity floor" loophole — Ridge can be beaten while SPY still wins.
   - **Turnover-adjusted Sharpe**: `Sharpe(daily_pnl - turnover_cost_bps · daily_turnover / 1e4)` with `turnover_cost_bps = 5` (CONTEXT default; overridden by `backtesting` configuration). A model whose Sharpe collapses past this haircut is paying for alpha with friction and is rejected.

   Decision gate: a model is promotable iff (Sharpe per fold > Ridge) AND (Calmar > 0.5 in ≥ 70% of folds) AND (PSR(0) > 0.95 in ≥ 80% of folds) AND (IR > 0 aggregate) AND (turnover-adjusted Sharpe > 0 per fold). Two-out-of-five is **not** enough; all five must hold. Borderline cases (one criterion missed by < 5%) get a manual review note in the SHAP report, mirroring the cycle-4 sample-weight ablation rule.

9. **Feature interaction terms (`gap × vol`, `mom × disp`) — deferred to v1.1, not v1.** Tempting to add: `gap_overnight × realized_vol_21d` (overnight news in a high-vol regime is qualitatively different from a quiet-tape gap) and `cross_sectional_rank_mom × xs_dispersion` (momentum works only when dispersion is high enough to differentiate). However: (a) LightGBM with `num_leaves ≥ 31` already learns 2-way and 3-way interactions implicitly through splits — adding hand-crafted interactions duplicates information and inflates the spec hash for no expected lift, (b) Gu/Kelly/Xiu 2020 explicitly tested hand-crafted interaction terms and found tree models extract them automatically. **Pin the decision: no manual interaction features in v1.** Revisit only if SHAP attribution analysis (Epic: SHAP reporting) shows the trees are systematically failing to split on a particular pair across folds — that's the empirical signal that the interaction is too weak for greedy splitting to find. Documented here to prevent a future contributor from adding `gap_x_vol` "because it seems obvious".

10. **Drift-monitor threshold calibration window (pinned).** The cycle-3 drift monitor pinned numerical thresholds (Stage 1 KS p < 0.01 for 5 days; Stage 2 PSI > 0.25 for 3 days; Frobenius > 0.3 for 3 days) but did not specify **how** the Stage 2 thresholds were arrived at or how to recalibrate. Decision:
    - **Initial threshold source**: PSI > 0.25 is the Siddiqi 2006 standard (already cited); Frobenius 0.3 is a literature-soft heuristic and explicitly flagged for calibration in CONTEXT line 128.
    - **Calibration protocol**: on the **first 6 months of OOS data** (a window with no known regime breaks), compute Stage 2 statistics in a rolling 21-day window vs each completed training fold. Record the empirical distribution of PSI and Frobenius. Set the production threshold to the **99th percentile** of the calibration distribution per statistic — so the false-positive rate is bounded at ~1% per day per statistic, ≈ 2 alerts/year per stat under stationarity.
    - **Recalibration cadence**: every 12 months, re-fit the calibration distribution on the trailing 6 months of post-incident-cleaned data; if the new 99th-percentile threshold moves by > 30%, log a `drift_threshold_recalibration` event to `observability` and require manual review before the new threshold takes effect (prevents the monitor from "learning" its way into blindness during a slow regime drift).
    - **Floor**: even after recalibration, PSI > 0.50 and Frobenius > 0.5 are **always** alert-worthy regardless of empirical distribution (these are "the universe changed" levels, not noise). Codified as `MIN_ALERT_THRESHOLDS` constant in the drift monitor module so a recalibration bug cannot silently disable production alerting.

## Improvements added beyond baseline (2026-05-17, cycle 4)
5. **Hyperparam search budget bound on M4 (pinned).** Optuna TPE is run with **`n_trials=50` AND `timeout=1800s` (30 min wall-clock), whichever fires first**, per refit. Rationale: monthly refit cadence × ~15 years of history × walk-forward train folds means the trainer is called O(180) times per full backtest; with the Mac mini M4 (16 GB / 10-core CPU, no GPU) a 50-trial LightGBM search on ~5 yr × ~500 names × 12 features fits a 25–35 min envelope per refit empirically (LightGBM `n_jobs=-1` uses all 10 cores; Optuna trials run sequentially to avoid memory thrash at 16 GB). A 30-min hard cap keeps a full historical backtest under 4 days of wall-clock and prevents a runaway trial (e.g. `num_leaves=4096` on a deep tree) from blocking the pipeline. The trainer logs `n_trials_completed` and `time_to_best_trial` to the manifest; if `n_trials_completed < 20` for any fold, the model is flagged for review (search undersampled). Pruner: `MedianPruner(n_startup_trials=5, n_warmup_steps=10)` to kill obviously bad trials early. **Bayesian (Optuna TPE) is the default over grid/random CV** because the search space is 6-D continuous (`num_leaves`, `learning_rate`, `min_data_in_leaf`, `feature_fraction`, `bagging_fraction`, `lambda_l2`) — TPE converges in 30–50 trials where grid-CV would need 1000+ to cover the same volume (Bergstra/Bengio 2012, *Random Search for Hyper-Parameter Optimization*). Grid-CV is reserved for the 1-D Ridge `alpha` sweep where it is provably optimal.
6. **Sample-weight uniqueness ablation — promotion thresholds (pinned).** The cycle-2 Sample-weight epic mandates an ablation but did not define what "improvement" means. Decision rule: **uniqueness-weighting is promoted to default iff (a) median per-fold IC delta ≥ 0 across ≥ 5 folds AND (b) cross-fold IC standard deviation drops by ≥ 15% (the documented López de Prado claim is variance reduction, not mean lift) AND (c) OOS Sharpe per-fold does not drop by more than 0.1 in any single fold**. Two-out-of-three is **not** enough — all three must hold, otherwise the simpler uniform-weighting wins by parsimony. The ablation runs on at least 6 walk-forward folds (≥ 6 months of test data) and the IC-variance delta + per-fold table is written to the manifest under `ablations.sample_weight_uniqueness`. If promoted, the next year's refits must re-verify on fresh OOS folds; a single year where the variance criterion fails reverts to uniform.
7. **Feature-side outlier handling (winsorization is for labels — features get a separate pipeline).** Cycle 2 pinned label winsorization at ±5σ but left feature outliers implicit. LightGBM is tree-based and robust to feature outliers in the **mean** sense (splits ignore magnitude beyond rank), but three features are computed from rolling regressions or ratios where a single bad bar produces a numerically unstable value that pollutes the rolling window for 21 days: `db_kyle_lambda_21d` (regression coefficient diverges if signed volume is degenerate), `parkinson_vol_21d` (log(high/low) with high == low → -inf), `db_signed_vol_imb_21d` (division by zero on a zero-volume bar). Decision:
   - **Per-feature clipping bounds fit on the train fold only** (same discipline as label winsorization): for each of the 12 features, compute the train-fold's 0.5%/99.5% quantiles, clip live values to that range, log the clip rate to `observability`. Clip rate > 1% on any feature for a 21-day window is an advisory drift signal (the feature definition has stopped matching its training distribution).
   - **NaN/inf policy at the feature boundary**: any feature returning NaN or inf for a (symbol, as_of) row causes that **row** to be dropped from the inference batch (logged as `feature_compute_failure`) — never silently imputed with 0 or the cross-sectional median (both inject phantom information). The `predict()` adapter returns no `Signal` for the dropped row; `strategy-engine` already handles missing names via its zero-signal-decay rule.
   - Implemented as the first transformer in `PurgedPipeline` (before z-score), so the clip bounds and z-score stats are both fit on the train fold within the same audited wrapper.

## Conventions
- Features are **pure functions** of (`bars_df`, `as_of_ts`) — no global state, no I/O inside the function, no implicit datetime conversion. Testable in isolation; reusable at inference unchanged.
- The feature module is imported by **both** training and `strategy-engine` runtime — duplicating feature code is the cardinal sin (training-serving skew). A parity test runs the same input through both code paths and asserts byte-equality on the output vector.
- Every training run produces a manifest:
  `{git_sha, data_window, feature_spec_hash, label_spec_hash, hyperparams, per_fold_metrics, aggregate_metrics, artifact_path, model_version, xs_zscore_snapshot}`
- **`feature_spec_hash` and `label_spec_hash` canonicalizer (pinned cycle 3):** both hashes are `sha256(canonical_json).hexdigest()[:16]` where `canonical_json = json.dumps(spec, sort_keys=True, separators=(",", ":"), ensure_ascii=True, default=str, allow_nan=False)`. `spec` is a plain `dict` built by `ml_research.spec.to_canonical_dict(...)` containing only JSON-native scalars (ints, floats, strings, bools, ordered lists of same). **Pickle, repr, and `hash()` are banned** — `hash()` is salted per-process and pickle byte-format changes across Python minor versions, both of which silently invalidate the model registry. The dict shape is: `{"version": 1, "features": [{"name": str, "fn_qualname": str, "params": {...sorted...}}, ...sorted by name...], "label": {"horizon_days": int, "winsorize_sigma": float, "zscore": "cross_sectional_daily"}}`. The `fn_qualname` is the fully-qualified import path (e.g. `ml_research.features.momentum.ret_21d`) — renaming or moving a feature function deliberately bumps the hash. A CI test computes the hash on a frozen golden spec and asserts the literal hex string is unchanged across commits; any drift forces an explicit version bump.
- Splits respect time order strictly. **Random shuffle is banned** in any code that touches a label.
- The simpler model is always the baseline. **LightGBM must beat Ridge in walk-forward OOS Sharpe per fold or it is rejected as overfit.** No "trust me" exceptions.
- Daily compounding is the optimization target — Sharpe matters more than raw return at this frequency because blow-ups break compounding (1 bad day at -20% wipes out months of +0.2% days).
- Walk-forward metrics (OOS Sharpe, IC, hit rate) are reported **per fold + aggregate** — a single summary number across folds hides the variance that determines if a model is deployable.
- `model_version` is an opaque string assigned by the registry. It travels with every `Signal` and every `decision_id` in `strategy-engine`, so a fill in `execution` can be back-traced to the exact training run and data window.
- `confidence` in the `Signal` output is derived from LightGBM quantile predictions: train a paired 0.1 and 0.9 quantile model alongside the mean model; `confidence = 1 / (1 + spread_normalized)`. Documented so it's not a magic float.
- Drift monitor runs daily after the close in **two stages** (refined cycle 3):
  - **Stage 1 — marginal**: KS-test each of the 12 features' distribution over the last 21 days against the most recent training fold's distribution. Emit p-values to `observability`; alert if any feature p < 0.01 for 5 consecutive days.
  - **Stage 2 — multivariate / dependence**: marginal KS is blind to **correlation drift** (a regime where each feature's marginal looks the same but the cross-feature dependence collapses or flips — exactly what happened at the 2020 vol-momentum unwind). Stage 2 computes two cheap multivariate statistics on the same 21d window vs the training fold:
    - **PSI on the top-3 PCA scores**: fit PCA on the training-fold standardized feature matrix, project both the training fold and the live window onto the top-3 components, bucket each score into deciles (training-fold quantile edges), compute `PSI = Σ (p_live - p_train) · ln(p_live / p_train)` per component. Standard interpretation (Siddiqi 2006, *Credit Risk Scorecards*): PSI < 0.1 = stable, 0.1–0.25 = moderate shift, > 0.25 = significant shift. Alert if any of the top-3 PCs has PSI > 0.25 for 3 consecutive days.
    - **Frobenius distance between correlation matrices**: `d_F = ||C_live - C_train||_F / ||C_train||_F`. Alert if `d_F > 0.3` for 3 consecutive days (threshold calibrated against historical training-fold-to-training-fold variation; tune on first 6 months of OOS data).
  - Both stages emit to `observability`; the strategy is paused via `control-plane` only on **Stage 2** alerts (correlation drift is the regime-change signal that actually invalidates the model; marginal drift is often benign re-scaling). Stage 1 alerts are advisory.
- Notebook outputs are stripped on commit (`nbstripout`); anything reused in production is promoted to the library first — notebooks never become a runtime dependency.

## Walk-forward harness — canonical splitter contract (binding on `backtesting`)
The `WalkForwardHarness` class in `ml_research.cv.walk_forward` is the **only acceptable splitter** for any time-series evaluation in this codebase. `backtesting` **imports** it and wraps it with a P&L replay layer; it does **not** re-implement walk-forward, embargo, or purge logic. Rationale: two implementations of purge/embargo will silently diverge, and the leakage-safety guarantees that anchor the shuffle-label canary depend on a single audited splitter (López de Prado, *Advances in Financial ML* Ch. 7).

Contract:
- Public API: `WalkForwardHarness(train_min_years=5, train_max_years=15, val_days=252, embargo_days=5, purge_days=1, test_days=21, refit_cadence="monthly").split(index) -> Iterator[FoldSpec]` where `FoldSpec = (train_idx, val_idx, test_idx, fold_id, fold_meta)`.
- Companion class: `CPCVSplitter(N=6, k=2)` in `ml_research.cv.cpcv` — Combinatorial Purged Cross-Validation (López de Prado *AFML* Ch. 12), used **inside** the train fold for hyperparam selection only. `.split(train_index) -> Iterator[(inner_train_idx, inner_test_idx)]`. Shares the same purge/embargo primitives as `WalkForwardHarness` via `ml_research.cv._purge.purge_embargo(...)` — single audited implementation, two thin wrappers.
- Both classes re-exported from `ml_research.cv` (i.e. `from ml_research.cv import WalkForwardHarness, CPCVSplitter` is the canonical import path used by `backtesting`).
- `backtesting.replay.WalkForwardReplay` **must** instantiate `WalkForwardHarness` and iterate its `FoldSpec` stream. Any other splitter (sklearn `TimeSeriesSplit`, custom rolling window, etc.) in `backtesting` is a contract violation.
- **Note on parameter naming** (resolved cycle 3): `backtesting`'s draft CONTEXT used legacy names `train_init=..., test_years=1`. The ratified names are `train_min_years` / `train_max_years` (expanding window, not fixed-init) and `test_days` (21 trading days, monthly refit cadence — not annual). `backtesting` must align its wrapper and its `tests/contracts/test_ml_research_imports.py` to the parameter names defined here; the CI signature test asserts `{train_min_years, train_max_years, val_days, embargo_days, purge_days, test_days, refit_cadence} <= set(sig.parameters)`. Annual refit + 1-year test folds are a `backtesting`-side configuration (`test_days=252, refit_cadence="annual"`), not a separate splitter API.
- CI test (owned by `backtesting`, asserted in its unit suite): `from ml_research.cv import WalkForwardHarness, CPCVSplitter` succeeds, and `isinstance(backtesting.replay.WalkForwardReplay._splitter, WalkForwardHarness)` holds. A second test asserts no module under `backtesting/` defines a class with `purge` or `embargo` in its name (AST scan), enforcing "wrap, don't replace".
- Symmetric CI test owned by `ml-research`: importing `backtesting` does not shadow or monkey-patch `WalkForwardHarness` or `CPCVSplitter`.
