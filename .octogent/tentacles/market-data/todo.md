# Todo

Bootstrap backlog for `market-data`. Each item is a self-contained agent-sized epic. Built around the ratified architecture in `CONTEXT.md`.

- [ ] **IBKR data client (`ib_async` wrapper)** — Thin wrapper around `ib_async` for the data API surface only (no trading). Connection pool with N `clientId`s (one for live, 4–8 for historical). Health check, reconnect with exponential backoff, structured logging with `correlation_id` from `shared-core`.
- [ ] **Universe registry + discovery** — Enumerate IBKR's tradable universe via `secDefSearchSpec` and `reqContractDetails` per asset class (equities, ETFs, futures, FX, crypto, indices). Persist to SQLite. Compute weekly 30-day ADV ranking. Emit the top-5,000 dollar-bar universe and the full-universe daily-bar universe.
- [ ] **Head-timestamp pre-pass** — For every (contract, whatToShow) pair in either universe, call `reqHeadTimeStamp` and persist. All backfill jobs read from this — never request non-existent data.
- [ ] **Pacing guard (shared token bucket)** — Rate-limit primitive: 60 req/10min per `clientId`, 6 req/2sec per (contract, exchange, tickType), 15s minimum between identical requests. All historical requests acquire from this before issuing. Includes the BID_ASK = 2 accounting rule.
- [ ] **ArcticDB storage layer** — Wrap ArcticDB with LMDB backend. Define libraries (`equity.dollar_bars`, `equity.daily_bars`, `future.dollar_bars`, `future.daily_bars`, `fx.dollar_bars`, etc.). Read/write/append API. Round-trip test that bars persist losslessly.
- [ ] **Daily-bar backfill (full IBKR universe × 30 yr)** — Sequential backfill using `reqHistoricalData` with `barSizeSetting='1 day'`. ~50k contracts × ~30 requests/contract ≈ 1.5M requests, ~7 days at 8 connections. Checkpointed per (contract, year). Resumable across restarts.
- [ ] **Historical tick backfill — one-shot (top 5k × ~6 months)** — **HIGH PRIORITY: IBKR tick retention is rolling — this opportunity expires daily.** Walk `endDateTime` backwards using `reqHistoricalTicks` (1000 ticks/req), build dollar bars in the same pass, write bars to ArcticDB. Raw ticks discarded after derivation. Per-contract resume on restart.
- [ ] **Live tick streaming + dollar-bar derivation** — `reqTickByTickData` per top-5k contract. In-memory rolling notional accumulator per symbol; emit dollar bar to ArcticDB the moment threshold is crossed. Bounded buffer per symbol; backpressure with alert on overflow.
- [ ] **Dollar-bar threshold calibration** — Per-contract threshold = function of 30-day ADV calibrated to produce ~50–100 bars/day on average. Recompute weekly. Threshold value stored in bar metadata for interpretability across recalibrations.
- [ ] **R2 cold-tier archive + transparent read fallthrough** — Background job: bar partitions older than N months pushed to Cloudflare R2 (free tier, 10 GB, zero egress). Read path falls through to R2 on local cache miss.
- [ ] **Cross-asset time alignment helper** — Helper to align bars across asset classes (US equities RTH, futures 23h, FX 24/5, crypto 24/7) into a common ML-ready feature matrix. Document timezone + session handling rules.
- [ ] **Bar-read API for downstream tentacles** — Read-only interface exposed to `ml-research`, `strategy-engine`, `backtesting`. Returns a polars/pandas DataFrame for `(symbols, date_range, bar_type)`. Backed by ArcticDB + R2 fallthrough.
- [ ] **Data quality monitor** — Emit metrics to `observability`: bars/day per contract vs expected from ADV, gap detection in live stream, ArcticDB write latency, IBKR pacing utilization, R2 cache hit rate.
