## Framework reference

### 1. Pre-trade check chain (run in order, fail-fast)

| # | Check | Formula | Why |
|---|---|---|---|
| 1 | `KILL_SWITCH_ACTIVE` | `not exists(HALT) and heartbeat_age < 300s` | If anything is wrong elsewhere, the operator (or a prior breach) flipped HALT — respect it before doing any work. |
| 2 | `SNAPSHOT_FRESH` | `snapshot.timestamp within today 09:30-09:35 ET` | A stale snapshot means equity/positions are wrong; sizing decisions on yesterday's equity can blow through limits. |
| 3 | `INTENT_NONZERO` | `abs(target_qty - current_qty) * mark >= $50` | Don't pay commission + slippage on rounding-noise rebalances. Also catches strategy bugs that emit zero-deltas in a loop. |
| 4 | `PRICE_BAND_FATFINGER` | `0.85 * prev_close <= mark <= 1.15 * prev_close` | Bad mark data (split not adjusted, decimal error) sizes orders 10x too large. Reject and HALT — never trade on a suspect price. |
| 5 | `MAX_SINGLE_NAME_NOTIONAL` | `target_notional <= 0.15 * NetLiq` | Single-name blow-up (fraud, halt, gap) capped at 15% of equity = max ~7.5% loss on a 50% gap. Survivable. |
| 6 | `MAX_GROSS_EXPOSURE` | `sum(abs(target_notional)) <= 1.0 * NetLiq` | No leverage in v1. Hard ceiling at 100% gross prevents an off-by-one in sizing from accidentally levering up. |
| 7 | `KELLY_CAP` | `target_notional <= 0.25 * kelly_optimal_notional` | Quarter-Kelly: Thorp showed full Kelly maximizes long-run growth but with brutal drawdowns; fractional Kelly trades a small fraction of growth for dramatically lower vol-of-vol. |
| 8 | `DAILY_TURNOVER_CAP` | `sum(abs(delta_notional)) <= 0.5 * NetLiq` | Once-per-day cadence shouldn't churn the book. Hard cap catches a strategy that flips long/short on every signal flip. |
| 9 | `POSITION_RECONCILES` | `\|broker_qty - internal_qty\| <= 1 share` | If our book disagrees with IBKR, we don't know our real exposure. Reject all intents until reconciled. |
| 10 | `FEATURE_SANITY` | `all features finite and within historical [p0.1, p99.9]` | ML pipelines silently emit NaN/inf or out-of-distribution garbage; never size off a feature you wouldn't have seen in training. |

### 2. Drawdown breaker triggers

- **Daily**: HALT at **-2%** of prior-day NetLiq. Resume next session only after manual ack.
- **Weekly (rolling 5 sessions)**: HALT at **-5%**.
- **Peak-to-trough**: HALT at **-10%** from 60-day high-water mark. Resume requires a written 1-pager post-mortem.

Empirical grounding: Kaminski & Lo (2014, "When Do Stop-Loss Rules Stop Losses?") show stop-losses add value for momentum/trend strategies with positive serial correlation; the optimal band sits where the cost of missing the rebound is balanced by the cost of riding the drawdown. For daily-compounded systematic strategies on liquid assets, -2% daily / -10% peak-to-trough is in the empirically supported band. The bot wakes up only once a day, so the breaker triggers at session start using prior session's close — no intraday whipsaw.

### 3. Position-limit philosophy

Daily-compounding Sharpe is destroyed by drawdowns far more than it's helped by peak returns: a -20% DD requires +25% to recover, costing ~3 months of edge at 8% annualized. The right limits are therefore **tighter than peak-return-optimal**. Use **quarter-Kelly (0.25)** as the default sizing fraction (Thorp, 2006), with a hard 15% single-name notional ceiling regardless of what Kelly says. Half-Kelly is the upper bound — only justified if you've validated the edge across >3 years out-of-sample.

### 4. Kill-switch mechanics (concrete design)

```
~/macminibot/state/
  HALT                  # presence = halt. Touch to halt, rm to resume.
  heartbeat.json        # {pid, ts_unix, version} written by risk_heartbeat.py every 60s
  halt_audit.log        # append-only: who, when, reason (manual or rule_id)
```

- `execution` checks both `HALT` existence AND `heartbeat_age < 300s` synchronously before every order. Either failing = no orders sent.
- `risk_heartbeat.py` runs from `launchd` (macOS native, more reliable than cron on a Mac mini), every 60s. If it can't write the heartbeat, the staleness alone halts trading.
- Drawdown breakers and check-chain failures `touch HALT` and write to `halt_audit.log`.
- Recovery: operator runs `risk-mgmt unhalt --reason "<text>"` which appends to the audit log and removes `HALT`. No GUI, no web dashboard — friction is the feature for a solo operator.
- No 24/7 on-call needed because the bot only acts once a day at 09:35 ET. If something breaks at 14:00, you have until tomorrow morning to fix it.

### 5. Risk-specific failure modes (what nobody else catches)

| Failure | Detection | Response |
|---|---|---|
| ML model returns NaN/inf in target_qty | `FEATURE_SANITY` + `INTENT_NONZERO` checks; type-assert at chain entry | Reject intent, log `ModelOutputInvalid` breach, HALT if >1 symbol affected |
| IBKR reports a position we don't know about (manual trade, corporate action, stale internal book) | `POSITION_RECONCILES` check at snapshot time | HALT immediately; require operator to reconcile and re-snapshot before resume |
| System clock drift vs. NTP > 2s | `risk_heartbeat.py` checks `sntp -t 1 time.apple.com` each tick | HALT; bad clock means bar timestamps are wrong, features are wrong |
| Daily-bar update failed overnight, dollar-bar feature uses T-2 data | `SNAPSHOT_FRESH` + check max(bar.ts) for each symbol < 36h | Reject intents for stale symbols only; HALT if >50% of universe stale |
| Limits-config file edited mid-session loosening a limit | Hash check at chain entry vs. session-start hash; loosening requires `--ack-loosen` | Reject the chain run entirely; require explicit ack |
| Strategy emits the same intent in a tight loop (bug) | Idempotency: dedupe intents by `(symbol, date)` per session; second emission rejected | Log `DuplicateIntent`, reject silently after the first |
| Account equity dropped overnight via withdrawal/deposit and limits are now mis-scaled | `NetLiq` delta vs. yesterday > 5% absent P&L explanation | HALT; force operator to acknowledge the cash movement |
| `strategy-engine` crashes mid-emission, only half the universe gets intents | Wait for `intents_complete` sentinel from strategy-engine before running the chain; timeout = HALT | HALT; don't trade a partial book — better to skip a day than rebalance half |
